# Тестові дані для фільтра руху та GPS

**Файли `accel_sample.csv`, `gps_sample.nmea` і `ground_truth.txt` це СПРАВЖНІЙ запис з плати від 01.11.2026**
(Pi 5 + плата Motion Logger, MPU6050 на I2C1, GPS NEO-6M на UART2, `scripts/record_accel.py`):
60 с спокою в руці, 60 с ходьби по квартирі, 100 Гц. GPS у записі віддає підроблену позицію (Ліма), тому
перевіряється лише розбір рядків. `make_synthetic_data.py` лишився для порівняння й сухих прогонів.

| Файл | Що це | Формат |
|---|---|---|
| `accel_sample.csv` | відліки акселерометра | `t_ms,x_g,y_g,z_g`, 100 відліків на секунду, рядки з `#` пропускаються |
| `gps_sample.nmea` | рядки NMEA від GPS-модуля | звичайний вивід модуля, рядки `$GP…*СУМА` |
| `ground_truth.txt` | що робилось насправді | `початок_с кінець_с still|walking` |
| `expected_report.txt` | еталонний вивід `analyze_recording` на цих даних | текст; оновлюється `make update-sample-report` |

Проміжки в записі: 0–60 с стою, 60–120 с іду. У NMEA перший рядок обрізаний (запис почався посеред
рядка), 158 рядків RMC/GGA мають позицію (підроблену), 82 без неї.

## Як замінити запис іншим (крок 1.6 виконано 01.11.2026)

1. Запиши на платі хвилину спокою і хвилину ходьби: числа акселерометра **в g** у `accel_sample.csv`
   у форматі вище (перший стовпець: мілісекунди від початку запису), GPS-рядки як є в `gps_sample.nmea`.
   Найпростіше скриптом (картка Pi OS, `sudo apt install python3-smbus2`, GY-87 на I2C1, GPS на `uart2-pi5`):

       python3 scripts/record_accel.py --out app/tests/data --phases still:60,walking:60 --gps /dev/ttyAMA2

   Скрипт підказує фази («лежить», «ходьба»), пише `accel_sample.csv` (100 Гц), `gps_sample.nmea` і
   `ground_truth.txt`. Сухий прогін без плати: додай `--fake` (дані синтетичні, у файлах позначено).
   GPS з цього екземпляра дає хибну позицію (підміна сигналу, див. нотатки), тож перевіряється лише розбір рядків.
2. Якщо писав вручну, перепиши `ground_truth.txt` за тим, що робив: наприклад `0 60 still` і `60 120 walking`.
3. `make update-sample-report` перегенерує `expected_report.txt`, потім `make check-samples`.
4. Підбери поріг і вікно: `./build/analyze_recording -w 50 -t 0.02 -c 50 tests/data/accel_sample.csv`
   (`-w` розмір вікна, `-t` поріг у g, `-c` скільки відліків підряд підтверджують зміну стану).
   Колонка `avg_dev_g` показує середнє відхилення: постав поріг між значеннями для «стою» і «іду».
5. Постав знайдені значення за замовчуванням (`core/motion_defaults.h`).

Підсумок запису 01.11.2026: у спокої середнє відхилення від повільного середнього ≈ 0,010 g, у ході ≈ 0,10 g
(шумовий поріг 0,02 g з вікном 50 відліків дає 0 помилок на 112 перевірених секундах і один `MOVE START` на 59,58 с).
Фільтр від фіксованої 1 g тут не працював: нерухомий датчик показував 0,942 g, відхилення 0,058 g.
