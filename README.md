# Motion Logger

Фінальний проєкт стажування Ajax Embedded Linux Internship: пристрій на **Raspberry Pi 5** збирає дані
акселерометрів (MPU6050 по I2C, ADXL345 по SPI) і GPS (NEO-6M по UART), визначає рух і пише лог.
Система збирається **Buildroot** у власний образ `sdcard.img`.

Цей репозиторій є **зовнішнім деревом Buildroot** (`BR2_EXTERNAL`): наш код і конфіги лежать окремо від Buildroot.

## Структура

| Шлях | Що там |
|---|---|
| `app/` | код застосунку і його `Makefile`: `core/` (буфер, фільтр, лог; без заліза), `interfaces/` (`sensor.h`: «дай відлік»), `drivers/` (звідки беруться відліки: поки програвач CSV), `main.c` (єдине місце, що з'єднує ядро з драйвером), `tests/` |
| `package/motion_logger/` | рецепт Buildroot для застосунку |
| `configs/` | defconfig образу: `motion_logger_defconfig` (`savedefconfig` від `raspberrypi5_defconfig` + наші зміни) |
| `board/motion_logger/` | файли плати: `rootfs_overlay/` (скрипт автозапуску), фрагменти ядра й BusyBox, DTS |
| `docs/` | документація, boot-логи (`docs/bootlogs/`) |
| `external.desc`, `external.mk`, `Config.in` | опис external-дерева (ім'я `MOTION_LOGGER`) |

## Збірка застосунку окремо (для розробки)

    cd app
    make                                   # на цьому комп'ютері
    make CROSS_COMPILE=aarch64-linux-gnu-  # для Raspberry Pi 5
    make STATIC=1                          # статична збірка (не залежить від libc на цілі)
    make DEBUG=1                           # з відладочною інформацією (-g -O0)
    make install DESTDIR=/tmp/rootfs       # встановити motion_logger в /tmp/rootfs/usr/bin
    make -n                                # лише показати команди, нічого не виконуючи
    make SANITIZE=address,undefined test   # усі тести з перевіркою пам'яті (make clean до і після)
    make analyze                           # інструмент аналізу запису акселерометра й GPS
    make check-samples                     # звіт на tests/data збігається з еталоном і з ground_truth
    make check-replay                      # програти tests/data через motion_logger --replay, події в лозі збігаються зі звітом
    make test                              # тести буфера і читача (лише на цьому комп'ютері)
    make test-tsan                         # те саме з перевіркою гонок даних
    make format-check CLANG_FORMAT=~/.venvs/clang23/bin/clang-format   # перевірка стилю
    make help

## Збірка образу

Потрібен Buildroot **2026.08** (окремий каталог, лише upstream):

    git clone --branch 2026.08 https://gitlab.com/buildroot.org/buildroot.git
    cd buildroot
    make O=../build-pi5 BR2_EXTERNAL=/шлях/до/цього/репозиторію motion_logger_defconfig
    cd ../build-pi5 && make

Образ: `build-pi5/images/sdcard.img`. Запис на картку: `dd if=sdcard.img of=/dev/sdX bs=4M conv=fsync`
(перевірте `X`: помилка зітре чужий диск). Повну збірку з нуля чекайте близько 1,5 години; після зміни лише
застосунку досить `make motion_logger-rebuild && make` (див. `CHANGELOG.md`).

## Схема підключення (плата Motion Logger на Raspberry Pi 5)

Нумерація пінів фізична (гребінка 40-pin); живлення модулів 3,3 В з пінів 1 і 17. Детальна схема й PCB
лежать в проєкті Altium (поза цим репозиторієм).

| Модуль | Шина | Пін Pi (GPIO) | Пін модуля |
|---|---|---|---|
| GY-87 / HW-290 (MPU6050 `0x68`, HMC5883L `0x1E`, BMP180 `0x77`) | I2C1 | 3 (GPIO2 SDA), 5 (GPIO3 SCL) | SDA, SCL |
| GY-291 (ADXL345) | SPI0, CE0 | 19 (GPIO10 MOSI), 21 (GPIO9 MISO), 23 (GPIO11 SCLK), 24 (GPIO8 CE0) | SDA, SDO, SCL, CS |
| NEO-6M (HW-623) | UART2 | 7 (GPIO4 TX), 29 (GPIO5 RX) | RXD, TXD (навхрест) |
| Кнопки | GPIO | 11 (GPIO17), 33 (GPIO13) | S |
| Світлодіоди R / G / B | GPIO | 13 (GPIO27), 15 (GPIO22), 31 (GPIO6) | через резистор 220 / 100 / 100 Ом |
| Налагоджувальний UART `DBG1` | UART0 | 8 (GPIO14 TX), 10 (GPIO15 RX) | USB-UART 3,3 В |

## Підключення до плати і перевірка

- Консоль: USB-UART 3,3 В на `DBG1` (115200 8N1; `picocom -b 115200 /dev/ttyUSB0`), TX адаптера на RX плати і навпаки.
  Повідомлення ядра йдуть на роз'єм JST (`ttyAMA10`), на `DBG1` лише getty та вивід `S99motion_logger`.
- Мережа: DHCP на `eth0`, SSH-сервер dropbear (користувач `root`, навчальний пароль задано в `configs/motion_logger_defconfig`;
  у продуктовому образі його прибрати).
- Автозапуск: `/etc/init.d/S99motion_logger {start|stop|restart|status}`, параметри в `/etc/default/motion_logger`.
- Перевірка заліза в образі (потрібні `i2c_arm` і `spi` у `config.txt` та модулі з `/etc/modules-load.d/`):

      i2cdetect -y 1        # очікується 68, 1e (після bypass), 77
      ls /dev/spidev0.0     # ADXL345 (DEVID 0xE5, SPI mode 3)
      gpiodetect; gpioinfo  # лінії кнопок і світлодіодів (libgpiod 1.6.5: gpioset gpiochip0 27=1)

  Це список для **навчального** образу; у продуктовому `i2c-tools` і утиліти libgpiod прибирають.
- Перевірка init-скрипта без плати: `sh board/motion_logger/tests/check_init_script.sh`.

## Імітатор датчика

    cd app && make
    ./build/sensor_sim | ./build/motion_logger --stdin --log motion.jsonl   # 100 чисел на секунду; Ctrl+C друкує підсумок

`sensor_sim` пише числа в канал раз на 10 мс, `motion_logger --stdin` читає їх через epoll у кільцевий буфер. Без `--stdin` програма нічого не читає й виходить (так її запускає автозапуск образу). З `--log` окремий потік дописує кожне число рядком JSON у файл: `{"t_ms":396411,"src":"sim","value":299}` (`t_ms` це монотонний годинник у мілісекундах, мітка ставиться в момент читання числа).

## Програвач запису акселерометра (замість справжнього датчика)

    cd app && make
    ./build/motion_logger --replay tests/data/accel_sample.csv --speed 50 --log motion.jsonl

Драйвер `drivers/csv_player.c` віддає відліки з CSV (`t_ms,x_g,y_g,z_g`) через інтерфейс `struct sensor` (`interfaces/sensor.h`); ядро не знає, що це файл, а не плата. `--speed 1` (за замовчуванням) це реальний час, `50` у 50 разів швидше, `0` без пауз (буфер може переповнитись, втрати видно в підсумку). У лог іде не кожен відлік (100 рядків на секунду це години логу, з якого людині треба вручну витягувати «коли я йшов»), а зміна стану руху й підсумок кожної секунди:

    {"t_ms":20550,"src":"accel","event":"MOVE_START"}
    {"t_ms":21000,"src":"accel","second":20,"moving":true,"avg_dev_g":0.2105}
    {"t_ms":40550,"src":"accel","event":"MOVE_STOP"}

Рух рахують ті самі модулі й ті самі параметри (`core/motion_defaults.h`), що й в `analyze_recording`, тому події в лозі збігаються зі звітом інструмента (це перевіряє `make check-replay`). Параметри (вікно 50 відліків, поріг входу в рух 0,03 g, поріг виходу 0,015 g, підтвердження 50 відліків) підібрано за двома справжніми записами 01.11.2026 (60 с спокою в руці, 60 с ходьби; 60 с «стою, іду, стою»); це записи однієї людини, для машини чи бігу їх треба перевіряти. Два пороги (гістерезис, як апаратне «неактивність» в ADXL345) потрібні, бо повільна ходьба просідає до 0,029 g, а тряска плати в руці сягає 0,028 g: з одним порогом вони не розділяються. Відхилення міряється від повільного середнього довжини вектора, а не від 1 g: справжній MPU6050 у спокої показав 0,942 g, і з порогом від 1 g спокій виглядав як постійний рух.

## Справжні датчики: IIO, послідовний порт (крок 5.2)

    ./motion_logger --iio /sys/bus/iio/devices/iio:device0 --iio-aux /sys/bus/iio/devices/iio:device1 \
                    --gps /dev/ttyAMA2 --log /var/log/motion.jsonl

| Параметр | Що робить |
|---|---|
| `--iio <каталог>` | основний акселерометр (MPU6050) через драйвер ядра: читає `in_accel_{x,y,z}_raw` і `in_accel_scale`, перераховує в g; з нього рахується рух |
| `--iio-aux <каталог>` | другий акселерометр (ADXL345), у лог не частіше рядка на секунду |
| `--iio-rate <Гц>` | частота опитування IIO, 1..1000 (за замовчуванням 100) |
| `--gps <порт>` | NEO-6M: читає рядки NMEA, по запису на кожен `RMC` |
| `--gps-baud <бод>` | швидкість порту (за замовчуванням 9600) |
| `--dump-raw <файл>` | поряд із логом пише СИРІ відліки основного акселерометра (`t_ms,x_g,y_g,z_g`, файл створюється заново); потребує `--log`. `analyze_recording` на цьому файлі дає ті самі події, що й лог (це перевіряє `make check-replay`) |

Яке з `iio:deviceN` який датчик, дивіться в `/sys/bus/iio/devices/iio:device*/name` (`mpu6050`, `adxl345`): нумерація залежить від порядку підключення драйверів, тож її перевіряють на платі, а не вгадують. Кожне джерело працює у своєму потоці й кладе записи в той самий кільцевий буфер; один потік-записувач розкладає їх у лог. Крім рядків `accel` у лозі з'являються:

    {"t_ms":21000,"src":"accel2","x_g":0.0123,"y_g":-0.0042,"z_g":0.9987}
    {"t_ms":21000,"src":"gps","fix":true,"lat":50.450100,"lon":30.523400,"speed_knots":0.30,"sats":8}
    {"t_ms":3000,"src":"gps","fix":false,"sats":0}

Поки модуль не спіймав супутників, координат у рядку немає зовсім (нульова широта була б вигаданою точкою на екваторі); `sats` це `null`, якщо рядка GGA ще не було. Без плати це перевіряють `tests/test_iio_accel.c` і `tests/test_gps_reader.c` (фальшивий каталог IIO та канал замість порту) та `make check-sources`, що запускає `motion_logger` з трьома джерелами одразу. **На справжньому залізі драйвер ще не перевірявся.**

## Кнопка й світлодіоди етапів руху (крок 5.4 і етапи 5.3)

    ./motion_logger --iio … --log /var/log/motion.jsonl --ui-gpio gpiochip0 [--ui-no-button | --ui-button-active-low]

Три світлодіоди (зліва направо на платі) показують етап руху: **1** (GPIO22) до першого руху, **2** (GPIO6, середній)
під час руху, **3** (GPIO27) після зупинки; далі, якщо рух почнеться знову, знову 2. Кнопка `BTN` (GPIO17) ставить
запис на паузу й знімає з неї: на паузі горять **всі три**, відліки забираються з буфера й відкидаються (у підсумку
рахуються як `paused`), а після паузи запис і фільтр руху починаються заново, тож етап знову «до руху». Дрижання
контактів ігнорується (200 мс після прийнятого натискання). `--ui-no-button` лише світлодіоди без кнопки,
`--ui-button-active-low` для кнопки, що дає 0 при натисканні. Опція вимагає `--log`; драйвер збирається лише з
`make GPIOD=1` (у Buildroot пакет робить це сам і залежить від `libgpiod`). Логіка (`core/recording_ui`,
`core/ui_controller`) перевіряється тестами на підробному `ui_io`, драйвер `drivers/gpiod_ui.c` на платі.
Порядок ліній світлодіодів перевірено на платі 01.11.2026; **кнопку (полярність KY-004) на платі ще не перевірено**,
тому автозапуск образу стартує з `--ui-no-button`. Лінія GPIO6 (середній світлодіод) після старту прошивки висить на
підтяжці до живлення й ледь тліє: `gpio=6=op,dl` у `config.txt` вимикає її ще з прошивки, а застосунок керує нею як виходом.

## Аналіз запису акселерометра і GPS

    cd app && make analyze
    ./build/analyze_recording [-w вікно] [-t поріг_g] [-c підтвердження] tests/data/accel_sample.csv tests/data/gps_sample.nmea

Друкує по секундах «рух так/ні» і середнє відхилення (g), події `MOVE START` / `MOVE STOP` з часом
та підсумок по рядках NMEA. Дані в `app/tests/data/` це **справжній запис з плати** від 01.11.2026 (див.
`app/tests/data/README.md`); GPS у ньому з підробленою позицією (Ліма), тож перевіряється лише розбір рядків.
Поріг і вікно підбираються цим же інструментом.

## Статус

Каркас (крок 2.1) і власний образ, що завантажується на Pi 5 (консоль на GPIO14, getty, dropbear). Готові: кільцевий буфер з замком (крок 2.2–2.3), читач на epoll з імітатором (крок 2.4), запис у лог (крок 2.5), одна команда `make test` і прапорці Makefile (крок 2.6), розбір NMEA, фільтр руху, події руху й аналіз запису (кроки 3.2–3.5 на синтетичних даних), поділ на `core/` / `interfaces/` / `drivers/` з програвачем CSV і події `MOVE_START`/`MOVE_STOP` у лозі (кроки 5.1 і 5.3 на синтетичних даних), читання IIO-акселерометрів і GPS з тестами на фальшивих джерелах (крок 5.2 без плати). Далі: перевірка на платі, коли буде корпус, і справжній запис для підбору порога.
